hz/timeq.py: corrected clock semantics
Records whose public date precedes the event date were labelled CONTRADICTORY. That
label was wrong: a trial is registered before it starts and a DOI is registered
before the issue date. 90 records in the export are in this state (clinicaltrials_gov
46, crossref 21, pubmed_eutils 17, nih_reporter 6) and they are a finding, not an
error. The class is now PUBLICATION_BEFORE_EVENT with a reason that says so, and it
is still ineligible for observability claims because the event had not happened yet.
Current export mix: FULL_TWO_CLOCK 1990, EVENT_ONLY 2928, PUBLICATION_ONLY 1484,
PUBLICATION_BEFORE_EVENT 90.

tools/refresh_audit_counts.py (new)
The audit's clock table is now derived from the export rather than typed by hand, so
it cannot drift again. Document counts refreshed (6,492 exported records; 2,928
EVENT_ONLY; 2,175 SNAPSHOT_ONLY; 954 regulatory records).
