# MedRadar 2.0 — Product Roadmap (next phases)

本文件只记录**下一阶段真正有价值的产品任务**，不把科研假设包装成路线图承诺。
状态基线：本轮 MVP 已交付（企业情报、比较、技术雷达、研究助手、证据浏览器、研究实验室）。

优先级判断标准：是否直接提升"用户能完成的研究任务"，而不是"功能数量"。

> **本轮（PR #12 统计修复）已完成**：LQ 统一分母与不适用状态、完整自然季度比较窗口、
> PMA 原始批准/补充申请分类与首次进入口径、同窗口监管路径结构、无效测试清理、
> 合成 fixture 的 Tier A/B 测试（CI 可无数据库运行）。详见
> [`PRODUCT_STATISTICAL_AUDIT.md`](PRODUCT_STATISTICAL_AUDIT.md)。以下 P0 为剩余项。

## P0 — 影响可信度的缺口（先修）

1. **人工复核 69 份证据包**
   当前 69 份证据包只有规则化 AI 预标注（45 Uncertain / 18 Routine / 6 Not Assessable），
   `final_label` 全部为空。研究处于 blocked 状态。产品已如实展示；下一步应完成具名人工复核，
   否则五家企业早期信号研究不能升级结论。

2. **赛道映射覆盖率**
   全库 `events.track_id` 覆盖率约 52%（审批记录约 45%–80%），未映射记录在产品中显示为"未映射"，
   不当作零活动。下一步：扩展产品代码→赛道映射、提供未映射清单供人工归类、并在企业页显示
   映射覆盖率变化。这是最容易造成"虚假趋势"的环节。

3. **企业实体映射治理**
   Dräger / Mindray 通过 21 + 10 条精确字符串补充映射，状态 `PENDING_HUMAN_REVIEW`；
   还有 13 条 "Draegar Medical Systems, Inc." 召回记录未归属。
   下一步：建立可审阅的实体映射台账（接受/拒绝/待定），并在证据页显示映射置信度。

4. **时间口径与增量更新**
   当前 `available_at` 基本等于发布日期，`first_seen_at` 几乎不可用，无法严格判断"何时首次可见"。
   下一步：为新增记录保存首次采集时间与版本，支持真正的 point-in-time 复查。

## P1 — 直接提升用户任务完成度

5. **数据源扩展（明确标注覆盖边界）**
   增加 EUDAMED、NMPA（仓库已有 demo 采集能力）、Health Canada、日本 PMDA 等，
   每个源单独标注市场、字段与起始时间。**不要**把美国 FDA 记录数当成全球排名。

6. **比较页增强**
   在同一赛道内按监管路径（510(k)/PMA）拆分；增加按企业规模/业务线的可比性提示；
   允许导出比较结果为 Markdown/CSV 并带引用 id。

7. **证据浏览器增强**
   保存筛选条件、复制引用（事件 id + 来源链接 + 日期）、按事件类型批量展开、
   对争议企业映射一键查看全部相关记录。

8. **研究助手增强（仍保持确定性）**
   增加更多意图（里程碑查询、时间窗内首次进入、企业×赛道矩阵）；
   可选接入 LLM 仅做"叙述改写"，输入严格限定为本次检索结果，输出必须保留引用且标注
   `narrative_source=llm`；默认关闭，不能成为 MVP 的运行前提。

9. **静态快照发布**
   生成只读的 GitHub Pages 快照（预计算五家企业 + 8 大领域），明确写"数据截止日、快照非实时、
   动态查询需本地后端"。当前没有声称 Pages 可运行 Python 后端。

## P2 — 科研与产品的桥接

10. **研究结论到产品卡片的受控管道**
    只有完成预注册验证并有人工复核的研究结论，才允许出现在产品页；其余只留在 Research Lab。
    需要一份"结论准入清单"与代码级 gate。

11. **预测能力验证**
    在 2027-Q3 前后才有成熟前瞻样本。此前不展示任何"已验证预测"。
    需要：预注册预测集、到期评分、校准曲线、失败案例公开。

12. **性能与缓存**
    当前本地 SQLite + LRU 缓存足够。若数据量或并发上升，再引入预计算聚合表（仍是只读派生层），
    不为性能提前引入微服务。

## 明确不做（除非目标变化）

- 不做需要付费 API 才能运行的核心功能；
- 不做无数据支撑的企业战略推断；
- 不做企业创新能力排行榜；
- 不在未完成人工复核时宣称研究结论；
- 不重写现有科研系统，不删除历史实验记录。

## 验收下一阶段的方式

每个 P0/P1 项都必须同时交付：
1. 可运行的产品行为（不是文档）；
2. 与真实数据一致的证据链；
3. 边界说明（哪些是观察、哪些是探测、哪些仍不确定）；
4. 可复现的验证记录。
