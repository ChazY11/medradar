## 二、发现并修复的真实问题

### 1. HORIZON 实验数字自相矛盾（P0-A）

报告写 **712 组 / 387 REJECTED / 325 UNKNOWN**，机器产物写 **726 组 / 0 REJECTED / 726 UNKNOWN**，两者出现在**同一个提交**里。

调查结论（有证据）：

- **官方结果是 726 / 0 / 0 / 726**。已用冻结输入离线复算，`EXP_H2_PAIRS.jsonl` 逐字节复现（SHA-256 `e7ad98e1…`）。
- **712 = 726 − 14**（HN3 硬负例），即 700 candidate + 12 HN4；不是去重导致。
- **387/325 是一次更早的运行**：同一判定函数、不同 S2 匹配器，算术自洽（5+93+156+191+267 = 712）。该匹配器源码**已不可恢复**，因此这是"重建算术"，不是"找回的旧运行"——报告里明确区分。
- 现行匹配器 S2 **命中 0 次**，所以"REJECTED 分支"根本是死代码 → **0 REJECTED 是预注册规则的正确输出**，不是 bug。
- 顺带修正 HORIZON 自己的一个说法：旧文案称"445 对共享型号 token"，实际是 **0**。

**修复**：在集成分支内更正两份 HORIZON 报告的措辞（仅此一处数字），并新建自动一致性闸门 `check_h2_consistency.py`——现在 73/73 通过、退出码 0；任何人再把旧数字写回去，CI 立刻失败。给 HORIZON 负责人的同款补丁已生成：`research/convergence/h2/HORIZON_PATCH_FOR_OWNER.md`。

### 2. 934 与 0 的跨国身份分歧（P0-B）

**不是算法冲突，是采样覆盖问题。** 见第三节。

### 3. 数据许可：受限数据曾被导出，且衍生数字仍在外泄（P0-C）

- UN Comtrade 条款 §5 原文禁止"复制、自动浏览或下载、再分发、出版或商业利用任何材料"，**须事先书面许可**；署名不能豁免。API 文档另允许程序化查询，因此三项权利必须分开：**可查询、可本地分析、禁止再分发**。
- HORIZON 自己的 `LICENCE_EVIDENCE.json` 为唯一受限源只登记了**两个 404 页面**，从未登记真正含 §5 的 `comtrade_license.html`——证据索引对关键条款是空的。
- **载荷已隔离，但衍生数字没隔离**：`INDUSTRY_DATA_REPORT.md` 仍印着 5 个中国进口单元格和精确值 `US$13,359,445,208.52`，`EXP_H4_INDUSTRY.json` 里也有。衍生数字同样属于再分发。
- **已处理**：载荷 30 个文件不进入本分支；衍生数字全部改写为"withheld"并附条款说明；精确值与汇率比值一并撤除。
- **另外发现 248 位英国采购买家的姓名+工作邮箱**被原样收录在 3 个原始 OCDS 包里（衍生导出并不需要）。已删除这 3 个文件（3,912,347 字节）。
- **没有发现任何凭据、密钥、`.env`、私钥或患者数据**（扫描 1,838 个 blob，17 条内容规则 + 9 条路径规则，全部误报均逐条说明）。因此**不需要轮换任何凭据**。

### 4. 62 条重复抓取被误当作独立记录（P0-C 附带）

导出清单里有 62 条记录是同一记录在多个企业切片下被重复收录。原来我的 staging 主键会把它们**互相覆盖**——这是我自己引入的缺陷，已修复：ATLAS 按版本追加，staging 日志保留每一次出现（occurrence 1…n）。这也意味着 **HORIZON 清单的记录数比真实独立记录多 62 条**。

### 5. 时间语义错误（转换层）

- 1,394 条记录没有首次观测时间。**原 ATLAS 的 `build_time` 会用抓取时间回填**——对 ATLAS 自己的采集是对的，对导入是**伪造观测史**。已改为保持空值并标记 `unknown_no_observation_log`。
- 90 条记录"公开时间早于事件时间"，只标记不"修复"，因为擅自选一个日期就是在造数据。
- 370 条记录事件日=公开日，这类记录**无法**用于提前量研究，已在 EXP-C4 里单独统计。

## 三、934 对 0 的最终解释

### 统一结论

**两者都是对的，测的不是同一件事。真正的分歧是 HORIZON 把一个采样结论写成了普遍语义结论。**

三个可复算的事实：

1. **HORIZON 的加拿大样本只有 49 个 MDALL `device_identifier`，其中 14 位 GTIN 形态的是 0 个，校验位合法的也是 0 个**，与它 320 个 GUDID UDI-DI 的交集是 **0**。因此"官方标识信号命中 0 次"是样本结构决定的，**不需要算法解释**。
2. HORIZON 因此在数据里写下了 `identifier_semantics`："MDALL device_identifier 不是 UDI-DI，与 FDA GUDID 不共享命名空间"。**这句话作为普遍命题是错的**——它对 99.67% 的记录成立，对少数 GTIN 形态的记录不成立。
3. ATLAS 扫描了 MDALL 全表 1,673,926 行，发现 **5,005 个 GTIN 形态标识（0.33%）**，查询其中 1,200 个，解析出 942 条 openFDA UDI 记录，确认 **934 对**精确 GTIN 匹配（934 条关系、934 个不同配对、934 个不同 GTIN、单次运行、无重复膨胀）。

### 这个"桥梁"有多大，能推广到什么范围

- **这是真实存在的官方跨国身份桥梁**，不是名称匹配：配对依据是同一个 GTIN-14，**934/934 全部通过 GS1 Mod-10 校验位**，934 个值两两不同、无重复配对，加拿大侧全部可从原始冻结表重建（标识符 + 许可 + device_id）。
- 但它是**一条窄桥**：MDALL 全表 1,673,926 行中只有 **5,512 行（0.329%）** 是 GTIN-14 形态，对应 5,005 个不同值、其中 4,927 个校验位合法。另有 **78 个 14 位数字串校验位非法**（均不在 934 之内）——"14 位数字"不等于"合法 GTIN"。
- **覆盖上限**：1,668,414 行（99.67%）根本没有可 join 的 UDI；按许可算 227/36,056（0.63%），按设备行算 679/146,183（0.46%）。
- **934 是下界不是总量**：只查询了 5,005 个 GTIN 中的 1,200 个（24%，系统性抽样），其中 934 个（77.8%）找到美国对应；其余 3,805 个值从未查询，因此**不可外推**。
- **企业归属基本不可得，且与"五家企业"几乎无关**：934 对中只有 **10 对（严格别名）/ 12 对（ATLAS firm_key）** 涉及 Medtronic、GE HealthCare、Philips、Dräger、Mindray 任一家，**98.9% 落在五企业范围之外**；**925/934（99.04%）** 的加拿大侧在冻结数据中没有任何公司字段（MDALL 标识符表本身不含公司列）。所以这些配对只能确认"同一个 GTIN"，**不能**确认"同一家企业"。
  - 这条修正了任务书里的假设：ATLAS 的 `missing_firms_in_bridge` 字面为真，但容易被误读成"桥梁由 Medtronic/GE 主导"，实际相反；其中 **760/934（81.4%）** 来自同一个加拿大许可（113873）与同一个美国 labeler。
- **层级与重复**：934 对中 **932 对锚定主 DI、2 对锚定包装 DI**（包装 DI 是较弱主张）；235 个 GTIN 出现在多行 MDALL 中，**47 对**涉及多行、其中 **43 对跨多个许可**——ATLAS 保留最后一行，因此这 43 对的**许可归属是任意的**（身份结论不受影响，许可归属不可引用）。
- 因此结论只能说到这个范围：**"在 MDALL 中占 0.329% 的 GTIN 形态子集上，存在可经官方标识独立复核的跨国设备身份桥梁；其余 99.67% 不能用 UDI 连接，需要第三种载体（例如 EUDAMED 的 Basic UDI-DI）或人工证据，不能靠名称相似性补。"**
- **绝不能**说成"全球设备身份问题已解决"，也不能说"该桥梁覆盖五家主要企业"。

详细证据与统一样本对照见 `IDENTITY_RECONCILIATION.md`。
