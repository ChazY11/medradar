# V1-001 / SCOPE

- 日期：2026-11-18
- 状态：本轮范围由任务书第八节与第十二节定义；本文档只做**边界声明**，不做论证。
- 上游：`docs/first_principles/001/FINAL_DECISION.md`（NARROW）与 `docs/refoundation/004/`。

## 1. 唯一产品问题

> MedRadar 能否每周可靠地发现、筛选、解释与**监护设备安全和性能**有关的重要公开变化，
> 并为 ICU / 床旁监护研发负责人提供比人工检索更有价值、可以核实的情报？

凡是不能回答这个问题的功能，本轮不新增。

## 2. 范围内（V1 只做这三件事）

| 编号 | 内容 | 本轮的交付形态 |
| --- | --- | --- |
| A | 监护设备召回、安全与性能证据的发现、身份归并、追溯 | 新的 FDA 召回适配器（复用现有 Adapter / Ledger / 准入链路）+ 可测试的监护设备筛选规则 |
| B | 历史档案 / 情报候选 / 可交付情报的分离；有实际区分度的重要性分级 | 派生视图（不新建存储）+ `grade_importance` + 周报生成器 |
| C | 四周前瞻性用户验证的准备与首期候选周报 | 方案、反馈表、对照流程、指标脚本、一份真实来源支持的候选周报 |

## 3. 设备范围（只这些）

多参数病人监护仪、中央监护站、ECG / 心律失常监测、SpO2 / 血氧、有创 / 无创血压、
脑氧与相关神经监护、监护报警系统、监护数据通信与影响患者安全的软件缺陷、
上述设备的召回 / 纠正措施 / 监管安全通知、有明确设备性能意义的研究。

判定依据只允许四类，且**任何单一依据都不是绝对判据**：

1. 经核实的 FDA 产品代码（来自 `config/radar/topics.json`）；
2. 官方器械分类名（openFDA `device_name`）；
3. 官方产品描述与召回原因文本；
4. 企业实体（**仅用于复核提示，永不单独构成监护设备判定**）。

不确定的记录进入 REVIEW，不删除、不改写。

## 4. 范围外（明确不做，本轮也不做准备）

- 全医疗器械行业的召回与安全事件（本次采集会存储，但会以“非监护”理由排除并计数，不进周报）；
- 影像、介入、牙科、体外诊断、骨科、耗材；
- 专利、招聘、财报、社交媒体、新闻聚合；
- NMPA / EU MDR / EUDAMED / Health Canada（**缺口，明确报告**，本轮不新增事实来源）；
- 技术图谱、企业科技树、对比工作台、预测研究的新功能；
- 新的相关性引擎、第二套账本、第二套企业注册表、第二套前端；
- 本地模型 / 模型训练 / 模型判断进入正式交付链路；
- 生产部署、远程分支推送、PR 合并（本轮最高权限是本地提交）。

## 5. 用户范围

一位（或少数几位）ICU / 床旁监护产品线的真实研发、产品或技术管理人员。
本轮**没有**完成用户访谈，因此所有“用户会喜欢 / 会使用”的说法都只能标记为假设。
