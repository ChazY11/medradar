# RELEASE-GATE-001 / 发布决定

**决定：CONDITIONAL GO（有条件放行）**

- 依据：19 项发布前检查中 17 项通过、2 项有明确条件（浏览器走查、监控安装）；
  无数据丢失、无不可恢复迁移、无性能回退、无核心业务不正确。
- 生效前提：下面 §3 的 6 条条件被**逐条接受或完成**。
- **本轮没有执行任何生产切换。** 下列内容都是"可以执行"，不是"已经执行"。

---

## 1. 为什么不是 GO

GO 意味着"没有已知不可接受的发布风险"。现在还差两条硬事实：

1. **没有真实浏览器走查过新前端。** 候选版本包含重新构建的 `web/dist`
   （`index-Bxn-0Rgq.js`，570 KB）。我验证了：语法通过 `node --check`、
   服务端 200、HTML 引用正确、bundle 内含 `DEGRADED`/`verdict`/`recall` 等新逻辑。
   **但没有验证它在浏览器里渲染正确**——入口需要 Basic 凭据，本轮不代用户登录。
   如果新 bundle 有运行时错误，公网页面会白屏，而 API 还是好的。
2. **监控单元尚未安装。** 探针与单元文件都准备好了、也在服务器上跑通了，
   但它们不在 `/etc/systemd/system` 里。不装 = 新版本进入"能跑但没人盯"的状态。

这两条都属于"一次变更内可以解决"，不构成 NO-GO，但不能在没解决的情况下宣称 GO。

---

## 2. 为什么不是 NO-GO

以下任何一条成立都应当是 NO-GO；本轮逐条排查后**都不成立**：

| NO-GO 判据 | 实测 | 结论 |
| --- | --- | --- |
| 迁移不可靠 / 可能丢数据 | 迁移 0.58 s，8,360/8,360/8,360/8,360/17,285/1,660 全部不变；**发现并修复了中断不可恢复的缺陷**，有 2 个回归测试 | 不成立 |
| 无法恢复 | 备份已校验；**恢复演练实际执行并通过**（integrity ok、已知记录一致、旧代码可服务该数据）；站外副本 sha256 一致 | 不成立 |
| 旧代码会写坏新库 | 实测旧代码**拒绝**打开 v3 且文件哈希不变 | 不成立 |
| 严重性能回退 | 2×2 分离实验：代码效应 +1.2%，数据效应 +100%；无代码级回退 | 不成立 |
| 核心业务不正确 | 6 个已知监护召回事件的身份/日期/企业/监管号/首次发现/回填标记逐条核对一致；API 全部 200 | 不成立 |
| 测试不全绿 | 1,706 通过 / 4 跳过 / 0 失败（1710 收集） | 不成立 |
| 磁盘/内存不够 | 磁盘 44 GB 可用；隔离 Web 195 MB，生产 Web 468 MB，available 1,496 MB | 不成立 |
