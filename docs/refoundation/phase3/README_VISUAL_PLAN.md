# README & front-page visual plan

**Task:** REFOUNDATION-003 / `task-20` (deliverable C) · branch `docs/ref003-navigation-readme`
**Scope:** images and caption/alt-text policy for `README.md`, `README.zh-CN.md` and the generated site.
**Not in scope:** a visual rebrand, new screenshots of unmerged UI, changes to `docs/dashboard.html` or
`docs/index.html` generators, or deleting any asset.

**Status:** draft. No asset was modified, moved or deleted by this task.

## 0. Method and limits

Every measurement below was read from `origin/main` (`b2a14c0`) with `git ls-tree`/`git cat-file`; PNG
dimensions were read from the IHDR header. Reference counts come from

```bash
git grep -l <file> origin/main -- '*.md' '*.html' '*.py'
```

**Limits.** Rendering on github.com (mobile wrap, table overflow, image scaling) was **not** captured,
so geometry findings are arithmetic (dimensions × rendered width), not screenshots. Current
GitHub page-width behaviour was not measured in a browser.

## 2. What changed in the README (this task)

The new `README.md` / `README.zh-CN.md`:

* keeps `docs/preview.png` but **moves it below the fold**, after the results and reproduce sections;
* adds an explicit caption carrying **dataset date + package version + "not a live service / not a
  forecast"**, in both languages;
* adds a machine-checkable **alt text** naming the artefact, version and dataset date;
* constrains the rendered width (`width="820"`) so the tall screenshot cannot dominate the layout;
* adds **Mermaid** for structure (architecture, and the implemented-vs-roadmap split) instead of new
  pictures;
* introduces **no new images** and no visual rebrand.

Rationale: the front page's job is to state the mission, the validation status and the negative
results. A 5200-px screenshot above that statement delays the only thing a scientific reader needs.
Demoting the image is a *truth* change as much as a layout change — the image is a snapshot of an old
dataset and must not read as "the current product".

## 3. Replace-later plan for the hero

The current hero is kept (no asset deletion) but is not the long-term answer. The target replacement:

| Requirement | Value | Why |
|---|---|---|
| Geometry | 1440 × 900 (16 : 10) or 1440 × 810 (16 : 9) | fits one viewport; text stays legible |
| Bytes | ≤ 200 KB | page weight; the current file is 489 KB |
| Content | dashboard **overview** view only, top-left region | it is the only view whose labels survive downscaling |
| Crop source | `docs/dashboard_overview.png` (1440 × 1000, 75 KB) | already committed, already correct dimensions, 6.5× smaller |
| Regeneration | `medradar dashboard` on a stated data snapshot, then crop | keeps the image reproducible, not decorative |
| Caption | `dataset YYYY-MM-DD · package vX.Y.Z · generated by medradar dashboard` | provenance is the point |
| Alt text | `MedRadar dashboard overview, package vX.Y.Z, dataset snapshot YYYY-MM-DD` | see §5 |

**[RECOMMENDATION]** Doing the crop is a one-command job (`medradar dashboard` → crop the top-left
1440 × 900). It is deliberately **not** done in this task: the replacement must be generated against a
stated snapshot by whoever owns the release, so the caption is true at the moment it ships.

## 4. Caption rules (mandatory, both languages)

Every image on the front page or the generated site carries a caption with four parts, in this order:

1. **What it is** — "Committed snapshot", not "MedRadar in action".
2. **Dataset date** — `dataset 2026-10-31`.
3. **Package version** — `package v0.5.0`.
4. **What it is not** — "not a live service", "not a forecast", "illustrates demo views".

Reference form (English):

> *Committed snapshot — dataset 2026-10-31, package v0.5.0. It shows the demo views of the generated
> report; it is not a live service and not a forecast. Rebuild with `medradar dashboard`.*

中文对照：

> *已提交快照 —— 数据集 2026-10-31、包版本 v0.5.0。它展示生成报告的 demo 视图；不是在线服务，也不是预测。
> 用 `medradar dashboard` 重建。*

**Rules**

| # | Rule |
|---|---|
| C1 | No image without a caption. A bare `![]()` is a review failure. |
| C2 | The caption must name the generating command (`medradar dashboard`, `medradar report`) so the image is reproducible. |
| C3 | A caption never contains a claim that is not also in the body text. |
| C4 | If the dataset date in the caption is older than the current snapshot, the caption says so: "older snapshot, kept for provenance". |
| C5 | Captions are structurally identical in EN and ZH — same four parts, same numbers. |
| C6 | No caption may imply a capability absent from the README *Validation status* table. |

## 5. Alt-text rules

| # | Rule |
|---|---|
| A1 | Alt text names **artefact + version + dataset date**, ≤ 125 characters. |
| A2 | Never "screenshot" / "image of" alone; never empty alt for a content image. |
| A3 | Alt text carries the **same claim strength** as the caption — screen-reader users must not receive a stronger statement than sighted readers. |
| A4 | No number appears in alt text that is not also in a provenance-bearing table in the body. |
| A5 | EN and ZH alt text are semantically identical (not machine-translated differently). |
| A6 | Purely decorative images are not allowed in this repository; every image is evidence. |

Current (compliant) examples in the new READMEs:

* EN: `MedRadar demo dashboard, package v0.5.0, dataset snapshot 2026-10-31`
* ZH: `MedRadar demo 看板，包版本 v0.5.0，数据快照 2026-10-31`

## 6. Style rules (no rebrand)

1. **Colour is inherited, not invented.** The project palette already exists in `docs/index.html`
   `:root`: `--accent:#1f4e79`, `--teal:#0f766e`, `--amber:#b45309`, `--red:#b91c1c`,
   `--green:#15803d`, `--bg:#f5f6f8`, `--ink:#17202a`. Badges, diagrams and future OG images use
   these tokens. No new brand palette.
2. **Light surfaces for the front page.** The dashboard is dark (`--bg:#0d1117`); a dark screenshot on
   a light README reads as a different product. Crop on light where possible, and check legibility on
   GitHub's dark theme too.
3. **Mermaid before raster.** Anything structural (architecture, workflow, layer split) is a Mermaid
   diagram with a caption, not a picture. Mermaid is diffable, translatable and cannot silently rot.
4. **Raster only for UI.** Screenshots are allowed only for generated UI, and only with a caption.
5. **Typography is structural.** There is no CSS control in Markdown: control hierarchy (≤ 3 heading
   levels), table use, and code-block language tags instead.
6. **No image that cannot be regenerated by a committed command.**

## 7. What this plan explicitly forbids

| Forbidden | Why |
|---|---|
| Screenshots of unmerged branches (#12–#30, ATLAS, HORIZON, …) | would present a draft as shipped |
| Mock-ups, wireframes, "vision" images | not evidence; the README is a status document |
| AI-generated charts or illustrations | fabricated imagery in a research repository |
| Hand-edited dashboard screenshots (annotations, arrows, labels added in an image editor) | unverifiable, and the annotation is a claim without provenance |
| Replacing a failing claim with a prettier picture | visual polish is not evidence |
| Deleting `docs/dashboard_*.png` to "tidy up" | they are provenance; unreferenced assets are archived, not deleted |
| New badge art | badges are derived from state, not designed |
