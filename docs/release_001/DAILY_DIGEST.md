## 3. 三条诚实规则（都是被数据逼出来的）

| 规则 | 为什么 |
| --- | --- |
| 来源日期晚于今天一周以上的，**标记并排在最后** | 那天的 1,660 条里有 **146 条**带有未来发表日期（会议摘要的期号）。把它们当"今天的新闻"是错的 |
| 同一工作的两条记录（正文 + 摘要）**合并成一行并计数** | 否则 Top5 会被同一篇论文占掉两席 |
| 待确认项**按准入分类报数**，不逐条罗列 | 17 条里 3 条是"安全/架构"类（桥梁监测、伪随机序列），逐条看只会浪费注意力 |

## 4. 技术实现

| 层 | 内容 |
| --- | --- |
| 后端 | `medradar/radar/digest.py` + `GET /api/radar/digest?hours=&limit=` |
| 数据来源 | 账本里的判定（`admission_current`）、其维度、来源状态。**没有任何模型生成的内容** |
| 计数口径 | `first_observed_at`（今天到货），不是发表日期 |
| 前端 | `web/src/components/DailyDigest.tsx`，挂在 /radar 顶部 |
| 语言 | 中英双语，跟随界面语言 |

**没有任何模型生成的内容** —— 每一条都指向一条可以点开、可以核查的记录。

## 7. 一个差点误判的"缺陷"

第一次移动端截图显示长标题被裁掉，看起来像溢出。实际是**无头 Edge 会把 `--window-size` 钳到最小宽度**，
按 `500px` 布局、按 `390px` 裁剪。

真正的验证方式：同源 iframe 包一层，量真实视口：

```
scrollWidth=375 clientWidth=375 overflow=false elementsBeyond=0
```

横向溢出为 **false**，越界元素 **0 个**。同时补了 `min-width:0` 与 `overflow-wrap:anywhere`，
让长标题在任何宽度下都换行。

## 8. 已知限制

| # | 限制 | 说明 |
| --- | --- | --- |
| 1 | 摘要窗口固定 24 小时 | 没有"看昨天/上周"的切换 |
| 2 | 排序用准入评分 | 评分是规则算的，不是"编辑推荐"；同分时按相关性再排 |
| 3 | 近重复只按标题归一化合并 | 措辞差异大的同一工作仍会分成两条 |
| 4 | 不含 AI 生成的摘要句 | 每个 top 项只有一行元信息，没有"这篇讲了什么"的一句话概括 |
| 5 | 空数据状态未在生产验证 | 单测覆盖；生产正在持续采集，造不出空天 |

第 4 条是下一步最值得做的：给每一条加**一句话概括**（来源摘要的首句，不加模型），这样"值得看"才真正可读。
