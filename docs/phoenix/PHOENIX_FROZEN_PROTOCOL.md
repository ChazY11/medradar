### 0.2 关键负面发现：不存在真正的 point-in-time 时钟

`04_time_semantics.json` 对全部 375,378 条事件逐类型验证：

```
available_at == published_at == event_date   对所有 kind 成立（差值恒为 0 天）
```

部分 `8k_catalyst` 记录带 `T00:00:00` 时间戳，但日期部分仍恒等。
`fetched_at` 全域集中在 **2026-10-30 / 2026-10-31 两天**——整库是**单快照**，不存在按时间累积的 as-of 历史。

**直接后果（必须写进所有结果页）：**

1. 数据库中的 `available_at` **不能**充当真实的"公开可获知时刻"。它是 `event_date` 的回填值。
2. 因此本轮**没有任何结果可以被称为第 4 类"真正具有独立前瞻验证的预测"**（任务书第七节）。
3. 本轮最高可声称的证据等级是**第 3 类：有保守公开时间约束的模拟预测**——而且这个"约束"必须由本协议人为注入，不能依赖数据库字段。
4. 单快照还意味着历史记录可能包含后来发生的回填/更正（例如赛道归属按当前配置回填到 2005 年的事件），这是**赛道归属时代错位（anachronism）风险**，见 §7。

### 0.3 因此采用的保守滞后注入

所有主实验在 **三个滞后场景** 下重跑：

| 场景 | 特征可用时钟 | 含义 |
|---|---|---|
| `L000` | `available_at` 原值（= event_date） | **名义时钟，仅作对照，不得作为头条结果** |
| `L090` | `available_at + 90 days` | **头条结果**。假设每年 4 次批量采集、审批类源存在数周行政滞后 |
| `L180` | `available_at + 180 days` | 压力测试 |

若某结论在 `L090` 下消失、只在 `L000` 下成立，则该结论必须标记为**对时序假设不稳健**。

### 0.4 无法检验的事项（记录原因，不制造结果）

| 事项 | 状态 | 原因 |
|---|---|---|
| 真正的前瞻预测验证 | **NOT TESTABLE** | 无 2026-10-30 之后的数据；无预先注册的前瞻观测登记 |
| 专利作为领先指标（SciTrends 核心） | **BLOCKED** | `medradar.sqlite` 无专利表；不采购外部专利数据 |
| 论文—专利关联与时滞（The Lens） | **BLOCKED** | 需付费授权数据；只做方法研究 |
| Review/Original Research 比例 | **PROXY ONLY** | 无出版物数据；仅可用 `PMA(高证据门槛)/510k(低门槛)` 作构念类比，**不得**称为同一变量 |
| 真实公开时滞分布 | **NOT TESTABLE** | 已核实字段恒等，无滞后信息 |
| 企业身份随时间变更（并购/更名） | **PARTIAL** | `companies` 表为 89 家静态注册表，无历史别名表；只能做敏感性分层 |

## 1. 数据契约

- 唯一数据源：`data/medradar.sqlite`，**只读**打开：`sqlite3.connect("file:...?mode=ro&immutable=1", uri=True)`。
- 禁止写入、禁止 `VACUUM`、禁止重建索引、禁止复制到工作区外。
- 每次实验运行必须重新核验 SHA-256 并记录到结果 JSON；不匹配则**中止**（`phoenix_common.verify_db()` 会返回 `sha256_matches_frozen`）。
- 分析窗口：`PANEL_START = 2004-01-01`，`PANEL_END = 2026-10-30`。
  - 理由：`company_key` 对器械事件的覆盖率在 2000 年代中期前不足 40%，而 89 家注册企业是单元级实验的约束瓶颈。2004 是覆盖率与样本量的折中点。
  - 敏感性：另跑 2009-01-01 起的窗口，报告结论是否改变。

### 1.1 双时钟规则（强制）

| 用途 | 使用列 |
|---|---|
| **特征**（模型输入） | `available_at (+ 场景滞后)`，**绝不**使用 `event_date` |
| **标签**（预测对象） | `event_date` |

理由：openFDA 器械端点从决定日到公开存在约 12 天滞后（`docs/SCHEMA.md` §8 实测）。用 `event_date` 造特征会引入未来信息。本库两列相同，所以这条规则靠 `L090/L180` 场景落地。

## 2. 预测任务（唯一规范，所有方法在同一批行上比较）

### 2.1 主任务 `T-CELL`（单元级：企业 × 技术赛道）

- **单元**：`(company_key, track_id)`，要求该单元在分析窗口内至少发生过 1 个事件。共 **1,116** 个单元。
- **时间原点** `q`：季度，`2004Q1 … 2025Q2`（共 86 个）。
- **标签**：
  ```
  y = 1  当且仅当  该单元在 (q, q+4] 四个季度内  event_date 落在其中的
           器械监管事件（kind ∈ {510k, pma}）数量 ≥ 1
  ```
- **行数**：67,084 单元-季度；有标签 62,732；正样本 12,517 → **发生率 19.95%**。
- **重复暴露说明**：同一单元相邻原点的 4 季前瞻窗口高度重叠。头条数字只在**每年 Q1 原点**（不重叠）上报告；全部原点仅作敏感性。

### 2.2 主任务 `T-TRACK`（赛道级）

- **单元**：`track_id`，59 个有 company×track 事件的赛道。
- **标签（增长）**：
  ```
  y = 1  当且仅当  前瞻 4 季平均设备事件率 ≥ 1.5 × 前 8 季均值
           且 前瞻 4 季设备事件总数 ≥ 3（绝对门槛，抑制小样本噪声）
  ```
- **行数**：4,904；有标签 4,255；正样本 406 → **发生率 9.54%**。

### 2.3 辅助任务

| 编号 | 定义 | 用于 |
|---|---|---|
| `T-ENTRANT` | 赛道 r 在 (q,q+4] 内首次进入该赛道的企业数 | H3, H6 |
| `T-HHI` | 赛道 r 在季度 q 的企业份额 HHI（按季度事件数计算份额） | H6 |
| `T-CP` | 赛道 r 的季度序列在 (q,q+2] 内存在一个已注入的真实变点 | H7 |

## 3. 时间切分（唯一允许的方案）

```
dev        2004Q1 – 2013Q4   模型与特征选择
validation 2014Q1 – 2021Q4   超参数与模型族选择
holdout    2022Q1 – 2025Q2   每个假设只用预注册模型评估一次
```

- **滚动起点（walk-forward）**：测试年 = 2014…2025，训练 = 该年之前的所有原点（扩展窗口）。共 12 折。
- **禁止**：随机切分、shuffle、k-fold、任何用到未来信息的标准化（scaler/imputer 只在训练折上 fit）。
- **禁止**：在 holdout 上做任何选择。看一次即需在报告中声明"已降级为探索性"。
- 所有泄漏检查见 §7。

## 4. 基线与模型（冻结；不得按结果临时增删）

| 代号 | 名称 | 定义 |
|---|---|---|
| **B0** | 发生率基线 | 预测训练折正样本率（常数）。等价于随机基线。 |
| **B1** | 历史持续性 | L2 逻辑回归，仅用自身历史计数特征 |
| **B2** | 移动平均/趋势 | 赛道上，用前 8 季均值与线性趋势外推作分数 |
| **B3** | 计数回归 | Poisson/NegBin GLM 于前瞻计数，分数 = 预测率 |
| **B4** | 变化点 | 自实现 PELT / CUSUM 于赛道季度序列，分数 = 变点后验强度 |
| **B5** | 统计模型 | L2 逻辑回归，全特征（标准化 + 中位数插补，训练折 fit） |
| **B6** | 轻量 ML | `HistGradientBoostingClassifier(max_iter=200, max_depth=4, lr=0.06)` |
| **B7** | 网络增强 ML | B6 + 企业-赛道二部图特征（度、PageRank、Jaccard 邻域活跃度） |

**B3/B4 是 H7 与 H10 的对照臂；B5/B6/B7 是"复杂模型是否真的更好"的检验臂。**
不得因为某个基线表现差就把它从报告中删除——**负面结果同样是结果**。

## 5. 指标（每个结果必须报这一整套）

**必报**：

- `n`、`n_pos`、`prevalence`（事件发生率）
- **AP / PR-AUC**（主指标；不平衡数据下 ROC-AUC 会过度乐观）
- `roc_auc`（仅作参考）
- **Precision@K / Recall@K / Lift@K**，K ∈ {5%, 10%, 20%}
- `brier`、`calibration_slope`
- **误报负担**：在固定告警预算（每季度 top-10 单元）下的精确率
- **可测量领先时间**：对 H2/H5，报告从信号被检出到目标事件发生的中位季度数（含右删失说明）
- **不确定性**：聚类 bootstrap 95% CI（单元级按 `company_key` 聚类，赛道级按 `track_id` 聚类，B = 1000，seed = 20261108）
- **稳定性**：按 3 年块（2014-16 / 2017-19 / 2020-22 / 2023-25）分别报告 AP；按 top-10 企业、top-10 赛道分别报告
- **模型间比较**：同一批行上的**配对**聚类 bootstrap 差值及其 p 值

**禁止**：只报一个漂亮的 accuracy。禁止报 accuracy（不平衡）。

**多重检验**：每个假设一个主检验 → H1–H10 共 10 个主检验，用 Holm-Bonferroni 校正（`phoenix_common.holm_adjust`）。族内次级检验单独列出并标注为"未校正、探索性"。

## 6. 十个假设的预注册定义与判定规则

判定规则在实验**之前**写定，按规则机械执行。

### H1 — 企业某技术赛道的监管活动是否有显著持续性？
- **检验**：`T-CELL`，AP(B1 持续性) − AP(B0 发生率)，holdout。
- **支持的判定**：ΔAP ≥ 0.05 **且** 配对 bootstrap p < 0.05 **且** 在 12 个 walk-forward 折中至少 9 折方向一致。
- **附加描述统计**：季度计数自相关（Spearman，聚类 bootstrap CI）；`P(active_{t+1} | active_t)` 与发生率匹配零模型的对比。

### H2 — 监管活动加速是否领先后续更密集的活动？
- **检验**：`T-CELL`，AP(含加速特征模型) − AP(仅水平特征模型)，holdout，单侧。
- **支持的判定**：ΔAP ≥ 0.02 且 p < 0.05 且在 ≥9/12 折方向一致。
- **附加**：定义"加速事件"（`accel > 0` 且前 4 季计数 ≥ 2），报告其后续 4 季率比与领先时间中位数。

### H3 — 赛道参与企业增加是否领先赛道整体增长？
- **检验**：`T-TRACK`，AP(含进入者特征) − AP(仅自身历史)，holdout。
- **支持的判定**：ΔAP ≥ 0.02 且 p < 0.05。
- **附加**：`corr(entrants_t, rate_{t+1..t+4})` 与置换检验；报告是否只是同期相关。

### H4 — 跨公司活动特征是否比单公司历史提供更多预测信息？
- **检验**：`T-CELL`，AP(自身特征 + 赛道上下文特征 B7 前的 B5) − AP(仅自身特征 B1)，holdout。
- **支持的判定**：ΔAP ≥ 0.03 且 p < 0.05 且 ≥9/12 折方向一致。
- **反证条件**：若 ΔAP < 0.01，明确写"H4 未获支持"。

### H5 — 历史临床试验信息是否为后续合格监管里程碑提供增量信息？
- **检验**：`T-CELL`，AP(自身器械历史 + 自身试验历史) − AP(仅自身器械历史)，holdout。
- **支持的判定**：ΔAP ≥ 0.02 且 p < 0.05。
- **限制**：试验与器械许可之间**没有**公开的设备级一一对应键，故这是"赛道内共变"而非"试验→许可因果链"。报告中必须写明。若有企业能在无试验的情况下通过 510k，则该企业的试验记录对 510k 无因果必要性——需分层报告。

### H6 — 技术赛道集中度变化是否能解释后续行业扩散？
- **检验 1（描述/关联）**：`ΔHHI_{t-4→t}` 与 `ΔHHI_{t→t+4}` 的 Spearman 相关（聚类 bootstrap CI）。
- **检验 2（增量预测）**：`T-TRACK` 上 AP(含 HHI 特征) − AP(不含 HHI)，holdout。
- **支持的判定**：检验 2 的 ΔAP ≥ 0.02 且 p < 0.05，**并且**检验 1 的相关系数 95% CI 不含 0。
- **说明**：HHI 定义必须按季度事件份额、赛道内、仅 `company_key` 非空事件；换用不同份额基数需作为敏感性报告。

### H7 — 时间序列变化点检测是否优于固定阈值异常检测？
- **设计（半合成基准，这是本轮唯一的受控实验）**：
  - 取 30 个数据量最大的赛道的真实季度序列（2004Q1–2025Q2，86 季）。
  - 在随机季度注入阶跃变化：倍数 m ∈ {1.5, 2.0, 3.0}，噪声用与真实残差方差匹配的负二项/泊松。
  - 无变化序列作为零假设，估计每季度误报率。
  - 检测器：**(a) 固定阈值**（率 > 2× 前 8 季均值），**(b) CUSUM**，**(c) 自实现 PELT**，**(d) SciTrends 式增长率阈值**。
  - 每个 (赛道, m) 组合 200 次重复 → 30 × 3 × 200 = 18,000 条序列 × 4 检测器。
- **指标**：真实变点 ±2 季内的检出率、每季度误报率、检出延迟（季）。**在误报率 ≤ 5%/季度 的匹配预算下比较检出率。**
- **支持的判定**：至少一个变化点检测器在匹配误报预算下的检出率比固定阈值高 ≥ 10 个百分点，且 18,000 次重复的 bootstrap CI 不含 0。
- **诚实标注**：这是**受控模拟实验**，证明的是检测器性质，**不是**"真实医疗技术历史中存在可检出变点"的证据。

### H8 — SciTrends 类型的增长特征能否迁移到医疗器械事件数据？
- **检验**：`T-TRACK`，AP(增长特征模型) − AP(B1 持续性基线)，holdout。
- **增长特征**（独立实现，非复制其代码）：多窗口增长率（1/2/4/8 季）、对数线性趋势斜率、`PMA/510k` 比值（作为 "高门槛占比" 构念类比）、加速度、波动率。
- **支持的判定**：ΔAP ≥ 0.03 且 p < 0.05。
- **明确限制**：不报"复现了 SciTrends 的精度"，因为预测对象、数据域、频率完全不同。专利领先指标**不可检验**（无专利数据）。

### H9 — 多数据源融合是否真的优于最强单数据源模型？
- **检验**：`T-TRACK` 增长任务。特征集四选一 + 融合：
  - `F_dev`（510k+pma）、`F_trial`、`F_recall`、`F_8k`、`F_fusion`（全部）。
- **支持的判定**：AP(F_fusion) − max_s AP(F_s) ≥ 0.02 且配对 p < 0.05。
- **反证条件**：若最强单源就是融合的 90% 以上，明确写"融合无实质增益"。
- **注意**：`8k_catalyst` 仅有 2015 年后数据（2015-01-02 起）。因此按源可用期分层报告，避免把"时间覆盖差异"误读为"信号强度差异"。

### H10 — 复杂网络或机器学习模型是否真的优于简单统计基线？
- **检验**：`T-CELL`，AP(B6/B7) − AP(B5)，holdout。
- **支持的判定**：ΔAP ≥ 0.03 且 p < 0.05 **且** ≥9/12 折方向一致 **且** holdout 上校准斜率不比 B5 差（差距 ≤ 0.2）。
- **反证条件**：若 ΔAP < 0.01，明确写"复杂模型未获支持，建议保留简单基线"。这是本协议预期最可能出现的负面结果之一，**不得因失望而调整判定标准**。

## 7. 泄漏与有效性审计（每个实验都必须跑）

| 编号 | 审计项 | 做法 |
|---|---|---|
| **L1** | 标签泄漏 | 自动化筛查：任一特征与标签 \|corr\| > 0.80 报警，> 0.95 判定为疑似泄漏（`phoenix_common.leakage_audit`） |
| **L2** | 未来信息 | 单测：把 `q` 之后的所有事件删除后重算特征，必须完全一致 |
| **L3** | 实体映射 | 报告 `applicant_raw` → 多 `company_key` 的映射冲突数量；报告 89 家注册表未覆盖的企业被丢弃的比例（覆盖偏差） |
| **L4** | 左截断 | 报告每单元 `exposure_q` 分布；对 `exposure_q < 8` 的单元做排除敏感性分析 |
| **L5** | 样本重复 | 头条数字仅用非重叠原点；重叠版本作为敏感性并标注依赖结构 |
| **L6** | 跨源错误对应 | 检查同一 `product_code` + 同一企业 + 同一日的重复记录；检查 510k 与其后续 PMA 是否被当作两个独立正样本（会导致正样本膨胀） |
