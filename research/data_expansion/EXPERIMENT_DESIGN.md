# DATA-EXPANSION-001 · 实验与评分预注册（结果之前冻结）

> **冻结时点：2026-11-09T05:40Z（在本轮任何实验数值产生之前）**
> **冻结方式：** 本文件与 `registry/SOURCE_SCORING_RUBRIC.json` 的 sha256 被
> `experiments/pre_registration.json` 记录；实验代码只读取这两个文件，不内联阈值。
> **允许的后续改动：** 只允许**追加**勘误（标注日期与原因），不得回改阈值、指标定义或判定规则。
> 若某条规则事后被证明不可执行，必须在 `SOURCE_INCREMENT_EXPERIMENT.md` 的"偏离预注册"一节
> 逐条列出：原规则、实际问题、改成了什么、为什么这不构成对结果的挑选。

本次预注册的目的是防止两类最常见的自我欺骗：

1. **看到漂亮的数据量就给它高分**（所以重复率与独立性是一等指标，不是脚注）；
2. **看到想要的提前量就把基线换掉**（所以基线、安慰剂对照与显著性阈值先写死）。

## 1. 锚点集（EXP-A / EXP-C 共用，先冻结再取数）

**冻结规则（生成脚本必须先于任何外部来源查询运行并落盘哈希）：**

- 来源：openFDA `device/510k` 与 `device/pma`，仅取 `decision_date` 在 **2017-01-01 … 2024-12-31**。
- 企业：Medtronic、GE HealthCare、Philips、Dräger、Mindray，企业归属用
  `identity.CompanyIndex.resolve` 的**确认级**匹配（`exact_alias`/`multi_field`），候选不算。
- 抽样：对每家企业，按 `(decision_date, 官方编号)` 升序排序，取**每个日历年第一条**，
  得到 ≤ 8 条/企业、≤ 40 条锚点。若某企业某年无记录则该年空缺，不补。
- 每条锚点记录：`anchor_id`（官方编号规范化）、企业 key、产品代码、决策日、器械名（原始字符串）。
- 产出：`experiments/anchors/ANCHORS.json` + `ANCHORS.sha256`。
- **复核**：与 PHOENIX-003 分支的 269 条锚点做交集统计，只报告重叠数，不修改对方资产。

冻结后，锚点集**不得因为结果不好看而增删**。

## 2. EXP-A — 新增来源覆盖率（增量证据）

**问题：** 在既有 openFDA 证据之外，每个新来源能给这些锚点补充多少**独立**证据？

**单位：** 锚点 × 来源。

**指标（逐来源报告，不合并成单一分数）：**

| 指标 | 定义 |
|---|---|
| `coverage_any` | 该来源至少提供 1 条**新独立**证据的锚点占比 |
| `evidence_per_anchor` | 每条锚点新增证据条数（中位数 + IQR） |
| `duplicate_rate` | 新增条目中 `canonical_key` 已存在于既有集合的比例 |
| `confirmed_link_rate` | 新增条目中企业关联为 `official_id`/`exact_alias`/`multi_field` 的比例 |
| `candidate_link_rate` | 关联为 `candidate` 的比例（单独统计，不进确认分母） |
| `cross_source_independence` | 锚点拥有的**不同上游机构**独立来源数（聚合平台不算新机构） |

**判定规则（先冻结）：** 某来源记为 `INCREMENTAL` 当且仅当
`coverage_any ≥ 0.10` **且** `duplicate_rate ≤ 0.50`；否则记 `NOT_INCREMENTAL`。
不满足样本量（该来源真实返回记录 < 20 条）时记 `INSUFFICIENT_EVIDENCE`，不得写成正面或负面结论。

## 3. EXP-B — 跨来源实体/产品关联准确性

**问题：** 不同关联策略（名称、名称+企业、监管 ID 锚定、多字段、语义候选）各自错多少、
拒绝多少？

**关键约束：没有可信标签就不算 Precision/Recall。** 本轮**没有人工标注预算**，
因此**禁止**报告总体 Precision/Recall/F1。可报告的是：

1. **权威可判定子集上的错误率**：只取"两个来源共享同一官方标识符"（同 DI、同 510(k)/PMA 号、
   同 NCT、同 DOI）或"官方标识符明确不同"的对，作为正/负标签。这是**权威事实**，不是人工判断。
   分母、抽样方式、以及"该子集不代表总体"的偏差必须逐条写明。
2. **拒绝率（refusal rate）**：匹配器主动返回 `none` 的比例。拒绝是正确行为，必须报告，
   不能被"覆盖率"掩盖。
3. **候选量**：`candidate` 条数与其置信度分布。候选不计入任何确认性指标。
4. **诱饵对照（decoy control）**：构造匹配负例 —— 同企业、日期偏移 ±2 年、不同产品代码的锚点对，
   测量各策略把它们误连的比例。这是 PHOENIX-003 F5 的做法，必须沿用。

**判定规则：** 只有同时满足"权威子集错误率 < 0.05"且"诱饵误连率显著低于真配对率"的策略，
才可标记为 `usable_for_confirmed_links`。其余只能用于召回候选。

## 4. EXP-C — 历史证据提前量（含安慰剂对照）

**问题：** 在监管决策之前，是否已经存在公开可得、且与目标技术相关的独立证据？分布如何？

**时间定义（不可变）：** `lead = event_at(锚点决策日) − source_public_at(证据首次公开日)`。
只有 `source_public_at_quality ∈ {exact, day}` 的证据可进入提前量统计；`coarse`/`derived` 只做描述。

**分桶（先冻结）：** `0-90d`、`91-180d`、`181-365d`、`366-730d`、`>730d`、`after_event`、`undatable`。

**两个证据强度层（必须分开报告）：**

- **T1（较强）**：证据文本中出现该锚点的**产品专名或型号**，且企业关联为确认级。
- **T2（较弱）**：仅命中该产品代码的**通用技术名词**。T2 基本等同于出版率，必须与 T1 分列。

**强制对照（缺一不可）：**

- **同源安慰剂（placebo）**：把锚点的决策日整体平移 ±365 天（保持企业/产品代码不变），
  用**完全相同**的查询与匹配流程重跑，得到安慰剂提前量分布。这是区分"真信号"与
  "该企业一直在发表"的唯一办法（PHOENIX-003 F4/F5 的直接教训）。
- **T2 基线占比**：报告 T2 在安慰剂上的命中率。若 T1 与安慰剂不可区分，结论只能是
  `NO_DETECTABLE_LEAD`。

**判定规则（先冻结）：** 只有当 T1 的提前量中位数与安慰剂分布的单侧置换检验 `p < 0.05`
且 T1 的 `confirmed_link_rate ≥ 0.7` 时，才允许写"检测到提前量"。否则写 `NO_DETECTABLE_LEAD`。

**C3 子实验（本轮对 PHOENIX-003 的增量贡献）：**
对 T1 命中的锚点，检查是否存在**非 FDA 的公开监管足迹**（EUDAMED / Health Canada MDALL /
TGA ARTG / 其他已接入注册库）且日期早于 FDA 决策日。报告：
- 可核查到的非 FDA 足迹条数；
- 因此应从"前监管"改判为"已有监管足迹"的锚点数；
- 该检查的覆盖率（哪些锚点根本没有可查的非 FDA 注册库）。
**"无法核查"不等于"不存在"。**

**必须写明的解释边界：**
- 回顾性找到较早公开的资料 ≠ 当时拥有可用预测信号；
- 任何依赖"事后才知道的实体关系"（如后来被收购的子品牌）必须单独标记并从 T1 剔除；
- 事后选择偏差：锚点是"最终成功获批"的产品，这本身是生存者偏差，必须写明。

## 5. 数据源优先级评分（权重在结果之前冻结）

十个维度，**0–4 分**，加权和 0–1（再乘 25 得 0–100 展示分）。
完整锚点定义见 `registry/SOURCE_SCORING_RUBRIC.json`（机器可读，含每个分位的判定标准）。

| 维度 | 权重 | 为什么是这个权重 |
|---|---|---|
| `accessibility` 可获取性 | 0.15 | 拿不到就没有一切 |
| `licence_and_cost` 授权与成本 | 0.10 | 合法与可持续是硬约束，但不是科学价值 |
| `time_credibility` 时间信息可信度 | **0.20** | 本项目全部科学主张都建立在时间语义上，权重最高 |
| `entity_linkage` 企业身份关联能力 | 0.15 | 跨来源关联的核心 |
| `product_linkage` 产品/技术关联能力 | 0.15 | 同上，且决定能否做产品级判断 |
| `historical_coverage` 历史覆盖 | 0.10 | 决定能否做长窗口回溯 |
| `update_stability` 更新稳定性 | 0.05 | 影响长期维护，不影响单次实验 |
| `complementarity` 与现有数据互补性 | 0.05 | 重复数据没有增量价值 |
| `early_evidence_potential` 潜在早期证据价值 | 0.03 | **刻意压低**：这是假设，不是已验证属性 |
| `maintenance_cost` 长期维护成本（反向） | 0.02 | 次要工程因素 |

**为什么把"潜在早期证据价值"压到 0.03：** 它是本轮最容易被过度乐观估计的维度。
若给高权重，任何"看起来像早期信号"的来源都会自动胜出，而本轮恰恰要检验这一点而不是假设它。

**分类阈值（先冻结）：**

| 分类 | 条件 |
|---|---|
| `ADOPT NOW` | 状态 `VERIFIED_API`/`VERIFIED_BULK_DOWNLOAD`，得分 ≥ 70，且 EXP-A 判定为 `INCREMENTAL` |
| `PILOT` | 状态 `VERIFIED_*`，得分 50–69，或已验证但 EXP-A 为 `INSUFFICIENT_EVIDENCE` |
| `RESEARCH ONLY` | 可用但存在重大时间/身份缺陷，得分 30–49 |
| `COMMERCIAL CANDIDATE` | `PAID_ONLY` 且得分（按可得性打折后）≥ 50 |
| `BLOCKED` | `BLOCKED_BY_POLICY` / `REQUIRES_REGISTRATION`（且无合法免费替代） |
| `REJECT` | 增量有限或质量不足：得分 < 30 且非付费 |

**禁止：** 用记录总量给分。评分输入一律是"去重后、可核实时间、可关联"的记录，不是抓到的行数。
