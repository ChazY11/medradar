# 执行摘要（给项目负责人）

**DATA-EXPANSION-001 · 2026-11-09 · 分支 `research/data-expansion-001`（基于 `main` = `b2a14c0`）**

---

**调查了多少来源？** 59 个，覆盖监管/UDI、专利、文献、临床试验、贸易、采购、招聘、资助、上市后九大领域。
每个来源都有结构化记录（`GLOBAL_DATA_SOURCE_REGISTER.json`）、真实的请求日志与响应切片。

**验证了多少真实接口？** **31 个**在无注册、无付费、无绕过的前提下返回了真实记录
（25 个官方 API + 2 个官方批量下载 + 4 个可解析公开页）；另有 9 个免费注册即可解锁、
4 个只能商业采购、11 个不可用、2 个被主动阻断。共发出约 700 次请求，**102 次失败全部留证**。

**最值得长期接入的？** 排序与理由写在 `PRIORITY_ROADMAP.md`：
开放文献三件套（OpenAlex / Crossref / Europe PMC）、临床试验（CT.gov + **新发现的 EU CTIS 匿名 JSON API**）、
以及**产品身份双锚**：AccessGUDID（DI）与 **Health Canada MDALL**（意外开放的免费 API）。
MDALL 是本轮最大的监管类收获——它让"非 FDA 监管足迹"第一次可自动化核查。

**找到新的医疗技术证据了吗？** 找到了**新通道**，没有找到**新结论**。
新增的是：EU CTIS 的欧盟试验、MDALL 的加拿大许可、FDA 短缺/进口警报的结构化解析、
UK Find a Tender 的招标—中标—签约三段对象。但本轮的所有实验都指向同一个负面结论（见下）。

**可量化增量？** 三项：
① **覆盖率**——在 38 个冻结监管锚点上，Crossref 覆盖 81.6%、OpenAlex 76.3%、USAspending 36.8%、
Europe PMC 34.2%、CT.gov 26.3%；NIH RePORTER 与 Semantic Scholar 不达标（0% / 2.6%）。
② **去重**——同一 DOI 在四个来源产生 4 条记录、**1 篇唯一论文（重复率 75%）**；
但企业级多源检索结果集重叠仅 0–9%，即**去重后多源仍然增加召回**。
③ **提前量：无。** T1 中位提前量 2,508 天，与日期平移安慰剂（2,593.5 天）**不可区分，p = 0.569**，
判定 `NO_DETECTABLE_LEAD`。这与 PHOENIX-003 独立复现了同一个负面结论（换来源、换查询、换锚点）。

**海关数据有企业级研究价值吗？** **在本轮条件下没有可用的合法入口。**
- 国家级统计（UN Comtrade、Eurostat）**免 key 即可验证**，但它们只能到"国家 × HS 编码"，**不能识别企业**。
- 唯一开放的企业级通道是 **UK HMRC trader 数据**（具名英国实体 + CN8 + 月份，五家全部命中），
  但它**没有金额、数量、伙伴或提单号**，只能证明"存在性"。
- 真正的企业级提单：ImportYeti 的 robots 明示禁止自动访问（一个请求都没发），
  ImportGenius / Panjiva / Datamyne 全部商业授权。
**结论：不要买提单数据来追供应链，除非先解决产品身份问题**——否则买来的数据同样无法与器械连接。

**需要购买商业授权的？** 4 个：ImportGenius（**$229/月起，是唯一价格公开的**）、
Panjiva（议价）、Descartes Datamyne（报价制）、Lens.org（机构订阅）。
但**本轮最便宜的解锁点其实是两个免费注册**：USPTO ODP key 与 EPO OPS 应用——
它们能打开**目前完全为零的专利通道**（7 个专利源在本轮拿到 **0 条**记录）。
注册属于需要您授权的动作，本轮刻意未做。

**发现的新问题？** 四个，都值得写进方法论文档：
1. **"能拿到"≠"能做时间敏感研究"**：31 个已验证源里，同时提供事件日、首次公开日与版本历史的**不超过 5 个**。
2. **跨源关联的瓶颈是产品身份，不是匹配算法**：仅名称匹配覆盖 84.2% 且对无关证据误连仅 0.3%，
   但**一旦要求企业确认，覆盖率跌到 18.4%、拒绝率 78.1%**。**没有任何策略可以安全用于确认级关联。**
3. **有 4 个来源会用成功状态码返回错误页**（Census 返回 200 + "Missing Key"、SAM.gov 返回 404 空 body 等）。
   状态码不是数据有效性证明。
4. **过程缺陷 2 起已披露并修复**：一次通配写入重写了 58 个 `SAMPLES.json`（样本本体未损，
   194 条目中 156 条哈希已从磁盘重算、**冲突 0**）；一次 61MB 响应导致挂起（已改为服务端聚合）。

**对下一轮最重要的建议？** **不要再加第 60 个数据源。**
EXP-B、C3、EXP-C 三个实验独立指向同一个瓶颈：**产品级身份**。
- C3 显示非 FDA 足迹检查**已经可跑**，但 11 个匹配里只有 2 个通过严格匹配，其余是品牌词误配
  （`Infinity` 同时是监护系统与呼吸气囊的品牌词）。
- EXP-B 显示企业确认把覆盖率打掉 4.5 倍。
**下一轮应该做的是**：把 AccessGUDID 的 **DI** 作为主键建产品身份表，
用 MDALL 的 `deviceidentifier` 端点做美国↔加拿大的 DI 级对齐；
**只有在产品身份可用之后，"能否提前发现"才是一个可测问题。** 在那之前，任何"提前量"结论都会退化成出版率的重述。

**一句话：本轮把"哪些数据能合法拿到"这件事做成了可复核的基础设施（59 源注册表、31 个已验证接口、
17 个连接器、688 条证据、174 个离线测试），并且诚实地证明了——按当前的数据与身份能力，
**提前量信号仍未出现**。下一步的价值不在数据量，而在产品身份。**
