# Cycle 2 — coverage, power, and the reality of the entry signal (2026-11-02)

## The pre-registered question

Is the weak cycle-1 first-entry signal limited by *measurement coverage* (51 firms, 25 positives
per window) or by *the world* (technology entry genuinely hard to predict)?

## What was done

1. **Deterministic applicant-entity universe** (`medradar/intelligence/universe.py`,
   `config/universe_v1.json`): 55,090 lane events → 10,309 raw applicant strings → 9,412 legal
   entities; 91.32% of events in detailed records, 8.68% in an explicit remainder bucket.
   No fuzzy matching. Dräger and Mindray — two of the five mandated focus companies — are now
   resolvable (they were absent from the curated roster).
2. **Harness validation** (`selfcheck_p1.py`): the parametric panel builder reproduces the frozen
   cycle-1 panel **exactly** — 41,003 examples, 503 positives, identical origins, identical
   per-origin candidate and positive counts, **0 feature mismatches**. The P1/P2 comparison is
   therefore attributable to the entity definition, not to a code change.
3. **Two panels, one protocol** (`run_cycle2.py`): P1 = 51 curated corporate parents
   (41,003 examples / 503 positives); P2 = 200-entity legal-entity cohort
   (161,636 examples / 1,082 positives, 193 active entities, 634 observed pairs vs 322).
4. **Cluster-aware inference + MDE + matched-FAR lead time** (`medradar/intelligence/evalstats.py`),
   applied per window and pooled (`analyze_cycle2.py`).

## Outcome

| | P1 curated parents | P2 legal entities |
|---|---|---|
| holdout rows / positives | 5,159 / 78 | 20,671 / 140 |
| pooled AP model | 0.1011 | 0.1292 |
| pooled AP persistence | 0.0446 | 0.0319 |
| ΔAP | +0.0564 | +0.0973 |
| pooled CI (entity clusters) | [+0.0054, +0.1036] | [+0.0426, +0.1697] |
| pooled CI (pair clusters) | [−0.0182, +0.1456] **includes 0** | [+0.0491, +0.1583] |
| windows excluding 0 (entity / pair) | 2/3 / 1/3 | **3/3 / 3/3** |
| MDE(80%) from observed SE | 0.0708 | 0.0877 |
| observed ΔAP vs MDE | below MDE | **above MDE** |
| pre-registered support condition | **not met** | **met** |

**Finding.** Widening the entity universe roughly doubles holdout positives and converts a
cluster-dependent, underpowered ΔAP into one that excludes zero in every pre-declared window
under both clustering choices and exceeds its own MDE. The cycle-1 negative was therefore
**partly a coverage artefact**, not purely a statement about the world.

**But the effect is modest and partly a baseline collapse.** AP 0.129 at a 0.68% base rate; the
persistence baseline falls from 0.045 to 0.032 as entities multiply, so much of the larger ΔAP
comes from the baseline deteriorating rather than the model improving.

## Negative and null results recorded

- **No earlier-warning effect.** At a matched false-alarm budget the model detects +0.30…+0.44 more
  of the eventual entries in every window, but mean lead time on those it detects is *shorter* in
  four of six windows (down to −31 days). The operational claim supported here is "finds more at
  the same noise budget", not "warns earlier".
- **The pre-declared heterogeneity split failed** (degenerate on both panels), so mission
  question 6 (does predictability vary with firm scale) remains unanswered.
- **Entity granularity is unresolved**: P2 splits corporate parents across subsidiaries
  (Medtronic = 30 entities). A true parent panel needs acquisition chains.
- **Cohort reproducibility gap, documented not hidden**: the panel ranks entities using the
  material-event rule, while the committed `config/universe_v1.json` ranks using all-row activity;
  the two 200-entity cohorts differ by 5 boundary entities (2.5%), explained in REPORT.md §2 and
  queued as a sensitivity run (B-017).

## What cycle 2 changes for the program

1. The default panel for entry forecasting is now the **entity cohort**, not the curated roster.
2. Any future "no effect" claim must be stated with an MDE, because the design-stage MDE for a
   26-positive window (≈0.39) is ~50× the marginal effects that cycle 1 was nulling.
3. Calibration is still unknown: no forecast has matured (B-015 remains blocked on wall-clock).
4. Next leverage is *data*, not model capacity: financial/market/publication nulls need
   re-testing on the larger panel before they can be called well-powered negatives.
