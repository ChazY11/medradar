# PILOT RESULTS — minimal historical replay (Phase 0)

**Status:** pilot only. Rule-based proxy labels, unadjudicated. **Not** a test of H1–H4, and no claim of detection
skill is made. Generated by `experiments/b083/pilot_replay.py` → `PILOT_RESULTS.json`.

## 1. What actually ran

| element | value |
|---|---|
| unit | firm × track × quarter |
| tracks | `imaging_us`, `respiratory` (the two confirmatory tracks from `DOMAIN_AMENDMENT_001`) |
| firms | GE HealthCare, Philips, Medtronic, Mindray (Dräger excluded — not evaluable) |

| availability | **Tier B**: an event is visible from `event_date + 30 days` (`EVIDENCE_TIME_AUDIT.json`) |

| M1 | the programme's validated detector: quarterly rolling z-score, threshold 3.5, 8-quarter baseline |

## 2. Leak audit

**0 violations** over every event that informs a score: for a decision at quarter *q*, all contributing events
satisfy `visible_at ≤ end of q-1`. The rule is recomputed independently of the pipeline rather than trusted.

**An audit defect was found and is reported rather than hidden.** The first version of the leak audit asserted that
each event must be visible *inside its own event quarter* and reported **118 spurious violations**. That is not the
property required — an event late in a quarter is legitimately observed in the next one. The corrected audit tests
the property that matters (visibility before the decision cutoff) and records the false alarm in this report.

**A second structure limits this pilot:** the alert is raised at quarter end, so an entry inside that same quarter can
at best be detected with **zero lead time**. Real lead time requires an earlier signal source, which this pilot did
not include.

## 3. Results (honest null)

| model | alerts | hits | false alerts | recall |
|---|---:|---:|---:|---:|
| M0 persistence | 2 | 0 | 2 | **0.000** |
| M1 z-score (deployed detector) | 1 | 0 | 1 | **0.000** |

Neither model detected any rule-based entry. **The most likely explanation is structural, not statistical:**

- 164 events over 6 cells × 32 quarters ≈ **0.85 events per cell-quarter**; a single new clearance moves a count from
  0 to 1, which against a sparse baseline gives z ≈ 1.8 — below the deployed threshold of 3.5.
- 9 positives across 6 cells is far too few to distinguish models even if the mechanism were right.
- A count-anomaly detector is built to find **sustained changes in the rate**, while Target A's entries are
  **single regulatory events**. Using one to detect the other is a specification mismatch.

## 4. What this establishes, and what it does not

**Establishes:** the pipeline runs end-to-end on real history (as-of snapshot → detection → alert → outcome check →
evaluation); availability can be enforced and independently audited; the sparse-cell constraint binds immediately.

**Does not establish:** any recall, precision, lead time or calibration claim; any statement about H1–H4; anything
about Dräger; anything about a real technology shift (no case has been adjudicated).

## 5. Consequences for Phase 1 (recorded before Phase 1 begins)

1. **Re-define the positive.** Target A must be a *sustained* change (e.g. ≥2 clearances in the track within 4
   quarters, or entry plus a second event within 12 months), not a single event. Otherwise the detector cannot
   possibly succeed and the study measures a mismatch it created itself.
2. **Pool across firms only within a track**, and report per-cell results separately; 9 positives cannot support an
   aggregate claim.
3. **Add an earlier source if lead time is to be measured at all.** Candidates that survive the tier audit: clinical
   trial registrations (Tier B, 55,592 records) and SEC 8-K disclosures (Tier B, sparse). Without them the study can
   measure *concurrent* detection only, and must say so.
4. **Confirmation must be independent**: a clearance confirmed by another clearance from the same firm in the same
   track is circular and may not be used.
