# RISK REGISTER — local small-LM research foundation

**Status of this register:** living document, first version 2026-11-04. **Owner of the register:** the Team Lead; each
row names the work package expected to act. A risk is only "closed" when its mitigation is *verified*, not when it is
described.

**How to use it.** `Likelihood`/`Impact` are qualitative (`H`/`M`/`L`) and deliberately not scored numerically — a fake
precision would imply a measurement nobody made. `Early-warning trigger` is the observable that says the risk is
materialising *now*; if it fires, the run stops and the trigger is recorded in the append-only run log
(`training/runlog.py`). `Status`: `OPEN` = no control yet; `MITIGATED` = a control exists and must be verified;
`ACCEPTED` = cannot be removed, so it must be reported; `WATCH` = dormant but one change away.

## Risks that may never be silently downgraded

* **R-05, R-06, R-15, R-16, R-17** — these are the risks that turn a project into a retraction. If any of their triggers
  fires, the affected result is withdrawn and re-run, and the withdrawal is recorded; it is never "adjusted".
* A change that *lowers* a risk rating must point to the evidence that closed it (a log line, a test, a measurement), not
  to a feeling of confidence.
