# hist_v1 — full-history company × track quarterly panel

Regenerable intermediate for the frozen pre-registration
`research/protocols/hist_v1_preregistration.md` (sections 2–3). It is **not** a
result and contains no model, no label and no outcome metric. Everything here is
production from the read-only event store; `eval.py` consumes `panel.json`.

## Exact command

```bash
python experiments/hist_v1/build_panel.py
```

Standard library only, no network, no randomness, no wall clock. The store is
opened `sqlite3` URI `mode=ro` and never written. Defaults can be overridden with
`--db`, `--research-db`, `--out-dir`, `--experiments-dir`; the command above is
the canonical one.

Outputs (all regenerated by that one command):

| path | role |
|---|---|
| `out/hist_v1/panel.json` | the panel (git-ignored; SHA-256 in the manifest) |
| `experiments/hist_v1/audits.json` | machine-readable entity / coverage / date / panel audits |
| `experiments/hist_v1/manifest.json` | SHA-256 + byte size of every input and the panel, row counts, command, worktree HEAD |

Determinism: two consecutive runs are byte-identical (panel SHA-256
`10f8c00aff51ad061f6aa237449a7dfb571ccf57fe4ea6705623cda0fd350e20`,
474,686 bytes; the manifest records and matches this hash).
`generated_at` is the maximum `fetched_at` in the store (data
snapshot time), not build time, precisely so regeneration is byte-identical.
The builder runs `_validate_panel()` before writing and aborts on any contract
violation (quarter labels, qidx bounds, iso→quarter consistency, aggregation
consistency, `sum(event_counts) == n_510k + n_pma`, `pairs_no_acquired ⊆ pairs`).

## Frozen rules actually applied

* Sources: `openfda_device_510k` (all 176,466) and `openfda_device_pma`.
* Material event: every 510(k); a PMA only if `payload.supplement_number` ∈
  {missing, null, `""`, `"0"`, `"S0"`} or `payload.supplement_type` contains
  `PANEL TRACK` (case-insensitive). This is identical to
  `experiments/reverse_rd_v2/run_v2.py`; it keeps 1,951 of 57,372 PMA records.
* Quarter: from `available_at` when present, else `event_date`. In this snapshot
  `available_at == event_date` for 233,838/233,838 source rows, so the declared
  decision-date-as-availability approximation is exact here.
* Track: `events.track_id`, else `config/product_code_tracks.json[product_code]`,
  else excluded and counted. The fallback rescued **0** events: every event
  without `track_id` also has a product code absent from the config file. The
  effective track universe is therefore `events.track_id` only (38 of 50
  configured tracks appear). `config/product_code_tracks.json` has **1,958**
  code→track entries; the 7,097 figure in the task leaf is the row count of the
  store's `product_codes` table, not this file.
* Company: the store's `company_key` when it is one of the 51 companies in
  `data/research.sqlite.companies`; plus Dräger and Mindray resolved by **exact**
  `applicant_raw` match to `config/hist_entity_aliases.json`. No fuzzy or
  substring matching anywhere.
* Grid: 1976-Q1 … 2026-Q2 (202 quarters). 2026-Q3 is partial and excluded.

## `out/hist_v1/panel.json` contract — `hist_v1.panel.v1`

Compact, key-sorted UTF-8 JSON. `qidx = (year − 1976) × 4 + quarter − 1`, so
1976-Q1 = 0 and 2026-Q2 = 201; index `i` of `quarters` is qidx `i`.

```json
{
  "schema": "hist_v1.panel.v1",
  "generated_at": "2026-10-31T03:55:55Z",
  "quarter_start": "1976-Q1",
  "quarter_end": "2026-Q2",
  "quarters": ["1976-Q1", "1976-Q2", "…", "2026-Q2"],
  "companies": [{
    "key": "medtronic", "display_name": "Medtronic",
    "cohort": "deep_case",              // "deep_case" (5) | "roster" (48)
    "total_material_events": 1298,
    "first_event_qidx": 7, "last_event_qidx": 201
  }],
  "tracks": [{
    "id": "cardiac_rhythm", "name_en": "Cardiac Rhythm",
    "category": "cardiovascular", "domain": "cardiovascular",
    "first_industry_qidx": 2, "n_firms_ever": 12
  }],
  "pairs": [{
    "company_key": "medtronic", "track_id": "cardiac_rhythm",
    "event_qidx": [7, 8, 9, "…"],        // sorted, unique, material events only
    "event_iso": ["1977-11-03", "1978-01-04", "…"],  // parallel; availability date
                                        // of the earliest event in that quarter
    "event_counts": [4, 5, 2, "…"],     // parallel; MATERIAL EVENTS in that
                                        // quarter (>=1). Use this, not the
                                        // quarter list, for activity counts:
                                        // sum(event_counts) == n_510k + n_pma
    "n_510k": 211, "n_pma": 31          // material-event counts (may exceed
                                        // len(event_qidx) when >1 per quarter)
  }],
  "pairs_no_acquired": [ /* same contract as "pairs", attribution sensitivity */ ],
  "audits": { "schema": "hist_v1.audits.v1", "reference": "experiments/hist_v1/audits.json",
              "entity_resolution": {…}, "track_coverage": {…}, "date_quality": {…},
              "panel_summary": {…}, "left_censoring": {…} }
}
```

`pairs` and `companies`/`tracks` are sorted by `(company_key, track_id)` and by
key/id respectively, so the file is diffable. `event_iso[i]` is the ISO
availability date of the earliest material event in quarter `event_qidx[i]`;
`event_counts[i]` is how many material events fall in that quarter, so
`sum(event_counts) == n_510k + n_pma` for the pair and per-quarter activity is
preserved (14,704 events collapse into 8,889 unique pair-quarters; a quarter
with 3 clearances has count 3). Per-quarter granularity is deliberate (the unit
of analysis is company × track × quarter): features such as
`firm_act_4 = log1p(company material events, last 4 quarters)` must sum
`event_counts`, not count quarters.

**`pairs_no_acquired` (added at the Lead's request, not in the frozen protocol):**
identical to `pairs` but with events removed when the company is one of the five
deep cases and the upper-case `applicant_raw` is neither a registry-accepted
exact alias nor contains the parent-brand token (`MEDTRONIC`, `GE`, `PHILIPS`,
`DRAGER` or `DRAEGER`, `MINDRAY`). Pairs with no remaining event are dropped.
It quantifies the *current-corporate-group attribution* look-ahead in the store's
`company_key` (Medtronic's pre-2015 Covidien/Tyco history). The 48 auxiliary
roster companies are unchanged because their brand-token sets are unaudited.
Default/primary analysis must use `pairs`; `pairs_no_acquired` is a sensitivity.

## Audit findings that can change interpretation

1. **The panel is 14.7k events, not 55k, and that is structural.** Funnel from
   178,417 material device events: 98,254 have no track mapping (55.1%), 153,676
   have no company in the 53-company universe (86.1%), and 118 fall after
   2026-Q2. Of the 24,741 material events of panel companies, only 14,822 also
   have a track; 14,704 survive the grid. Company coverage is the binding
   constraint: only 61,149 of 233,838 device rows carry a `company_key` at all
   (26.2%; 510(k): 13.4%). This is the pre-declared external-validity limitation,
   now measured.
2. **The store `company_key` is a current-corporate-group mapping.** 217
   Medtronic panel events (30 panel-source `applicant_raw` strings — 44 including
   non-device sources: Covidien, Tyco Healthcare, Kendall, Valleylab, Nellcor,
   Given, Bellco, Medicrea…) predate Medtronic's ownership and are attributed
   retroactively; removing them drops Medtronic 32 → 31 pairs. GE/Philips/Dräger/
   Mindray have 0 such panel events (all their strings are parent-branded).
   `pairs_no_acquired` isolates this.
3. **Entity deny list has one real entry and removes 0 panel events.** `Björn
   Philips` — a ctgov clinical-trial investigator name — was token-matched to
   Philips by the store's token-containment mapping (surname token `PHILIPS`); it
   is not a legal name/brand/subsidiary, so it is denied. It has no panel-source
   (510(k)/PMA) event, so applying the deny list removes **0** panel events
   (documented zero). No string with panel-source events belongs to an unrelated
   company; the task's illustrative `Surge Medical Sales` does not occur in the
   store (a `%SURGE%`/`%SALES%` scan only finds such strings with
   `company_key = NULL`). Divisions/business units/product lines are accepted as
   unambiguous corporate attribution. 416 strings are audited in
   `audits.json` — every store-assigned string per deep case, including the
   non-device sources — plus all 32 Dräger/Mindray registry aliases.
4. **Registry defect fixed:** `"Draeget Medical AG & Co. Kgaa"` (2 510(k), a
   typo) was missing and silently dropped; added with recorded evidence
   (`config/hist_entity_aliases.json` `refinement_history`). Panel impact: +1
   event (the other record has no track), +0 pairs. `"Drager Safety"` is now
   explicitly in `reject_exact` (1 record, non-medical division).
   `"Draegar Medical Systems, Inc."` (13 rows) is recall-only and was left
   unadded for human review.
5. **The single-token `DRAGER` attribution test is wrong and was corrected.** The
   German umlaut transliterates to `Draeger`, which does not contain `DRAGER` as
   a substring; a literal test would have removed 108 of Dräger's 133 events.
   Both orthographies are used, and registry-accepted aliases are always
   parent-attributed. `audits.json →
   entity_resolution.attribution_sensitivity.known_quirk` records this.
6. **Date quality is clean:** 0 rows with `available_at < event_date`, 0 missing,
   0 `available_at > event_date`; both sources exactly `available_at ==
   event_date`.
7. **Left censoring:** 25 pairs have their first panel event in the first four
   grid quarters (1976-Q1..Q4), 0 in 1976-Q1 itself. The store's 18 material
   pre-1976 PMA approvals belong to no panel company, so grid truncation removes
   0 panel events — but pairs whose first clearance is pre-1976 remain
   indistinguishable from never-entered pairs, as the protocol declares.
8. **Track taxonomy coverage is very uneven by decade** and is biased toward
   recent codes (2010s: 17,582/30,476 510(k) mapped vs 1970s: 1,998/7,608).
   Top unmapped codes: LYY 1,947, `<NULL>` 1,340, LZA 1,177, EBF 879, DQY 802.
   Applying today's unversioned mapping to history can make a track look younger
   than it was (protocol §12.4); `track_age` must be computed from events.

## Limitations inherited from the protocol (not corrected here)

* **Left censoring** (store starts 1976 / PMA 1968; pre-1976 entry unknowable).
* **Entity resolution**: the 51-company auxiliary roster mapping is unaudited
  and is the main external-validity limitation; the five deep cases are audited
  string-by-string here. Corporate group = current group, not point-in-time
  (quantified in item 2).
* **Availability approximation** = FDA decision date (exact equality in this
  snapshot; historical publication lag unobservable).
* **Taxonomy** is current and unversioned; applied to history it may distort
  track age and track-level counts (measured in item 8).
* **Materiality rule** excludes 96.6% of PMA records (55,421 of 57,372
  supplements); this is intentional, but it means PMA-heavy firms (notably
  Medtronic) are represented by far fewer material events than their store
  footprint suggests.
* **2026-Q3 partial** quarter excluded; 118 mapped events after 2026-Q2 are
  outside the panel (they cannot be a label in the evaluation window).
